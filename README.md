# MARKETING COMPANY — 공식 홈페이지 첫 버전

신규 온라인 마케팅 회사의 원페이지 소개·상담 사이트입니다. **MARKETING COMPANY는 임시 상호이며 실제 확정 브랜드가 아닙니다.** 기존 음식점이나 다른 업체와 관계없는 신규 사업용 초안입니다.

## 실행

Node.js 24.x를 사용합니다. `.nvmrc`와 `package.json`에 로컬·Vercel 빌드 버전을 맞췄습니다.

```sh
npm install
npm run dev
```

터미널에 표시되는 http://127.0.0.1:5173 에 접속합니다.

```sh
npm run verify
npm run build
npm run preview
```

빌드는 TypeScript 검사 후 `dist/`에 정적 사이트를 생성합니다. 프리뷰 기본 주소는 http://127.0.0.1:4173 입니다.

## 구성과 수정 위치

- `src/config/company.ts`: 회사명, 로고 텍스트, 소개 문구, 연락처, 도메인, 공유 이미지 설정. 미등록 정보는 빈 값으로 유지합니다. 현재 연락처 및 사업자 정보는 화면에 표시하지 않습니다. 확정 후 설정과 표시 UI를 연결해 주세요.
- `src/data/content.ts`: 서비스 6종, 사업 유형별 추천, 운영 원칙, 진행 과정, FAQ. 추후 서비스별 상세 화면으로 확장할 수 있는 고유 ID를 사용합니다.
- `src/components/ConsultationForm.tsx`: 입력 필드와 오류·제출 중·테스트 완료·실패 상태.
- `src/lib/inquiry.ts`: 폼 데이터 타입, 검증, 실제 API로 교체할 제출 함수.
- `src/App.tsx`: 원페이지 섹션과 메뉴, 사업 유형 탭, 서비스별 상담 연동.
- `src/style.css`: 반응형 레이아웃과 모션 감소 대응.
- `index.html`: 한국어 문서, 기본 title·description. 회사 설정은 실행 시 메타데이터에 반영합니다. 검색 및 소셜 크롤러 대응을 위해 운영 전 확정 메타데이터를 이 파일에도 반영하세요.

## 구현 내용

- 모바일 메뉴, 내부 앵커 이동, 모바일 하단 상담 버튼
- 서비스별 상담 자동 선택, 사업 유형 추천 탭 및 추천 서비스 일괄 선택
- 방향키·Home·End로 조작 가능한 탭, Escape로 닫는 모바일 메뉴
- 네이티브 FAQ 아코디언, 본문 바로가기, 명시적인 레이블과 포커스 표시
- 업체명·담당자명·연락처·업종·상담 내용 검증, 선택 이메일 형식 검증
- 국내 연락처(공백·괄호·하이픈 허용)와 +국가코드 형식 지원
- 오류 메시지 연결 및 첫 오류 필드 포커스, 제출 상태 안내
- `prefers-reduced-motion` 대응 및 모바일·태블릿·PC 레이아웃

## 문의 폼의 현재 상태

실제 문의 수신 서버가 없습니다. **테스트 제출은 실제 전송이나 접수가 아니며, 입력 내용은 서버·콘솔·분석 도구·브라우저 저장소에 남기지 않습니다.** 새로고침 시 입력 상태가 초기화됩니다. 처리 중 상태를 확인할 수 있도록 제출 함수에 짧은 대기만 둡니다. 개인정보 안내와 확인 체크박스는 검토용이며 운영용 법적 동의문이 아닙니다.

## 운영 전 확정할 사항

1. 상호, 로고 및 최종 소개 문구.
2. 실제 연락처·이메일, 대표자·사업자등록번호·주소 등 사업자 정보와 필요한 공개 항목. 현재는 임의로 만들어 넣지 않았습니다.
3. 실제 도메인과 공유 이미지. 확정 전 가짜 canonical URL 및 미확정 정보의 구조화 데이터는 생성하지 않습니다.
4. 개인정보 수집 주체, 수집 목적·필수/선택 항목·보유기간·동의 거부 관련 안내 및 처리방침. 검토 후 실제 동의 UI와 안내를 확정하세요.
5. 서비스 작업 범위·견적·계약 기간·광고 매체비 및 운영비 구분.

## 실제 수신 및 배포를 위한 후속 작업

- `submitInquiry`를 HTTPS API에 연결하고 서버에서도 입력을 검증합니다. 개인정보를 URL·로그·분석 이벤트에 포함하지 않습니다.
- 서버의 보안·접근 권한, 스팸 방지, 요청 제한, 보관·삭제 정책과 수신 담당자를 정합니다.
- 실제 API 응답 기준의 접수 성공·실패 표시를 구현하고 테스트용 문구와 검토용 개인정보 문구를 교체합니다. 전송 실패 및 중복 제출도 확인합니다.
- HTTPS를 지원하는 정적 호스팅에 `dist/`를 배포하고 확정 도메인을 연결합니다. API를 별도 운영하는 경우 CORS를 허용 도메인으로 제한합니다.
- 회사 확정 정보에 맞춰 title·description·OG 이미지 및 필요 시 canonical URL을 설정하고 모바일·데스크톱 실기기에서 확인합니다.
- 현재 글꼴은 Google Fonts의 Noto Sans KR을 불러오며, 연결이 없으면 시스템 글꼴로 표시됩니다. 자체 호스팅이 필요하면 글꼴 라이선스를 확인한 뒤 교체할 수 있습니다.

로그인·관리자·결제·예약·음식 주문·고객 관리·카탈로그 다운로드는 포함하지 않았습니다. 이 작업에는 외부 배포와 실제 문의 수신 연결이 포함되지 않습니다.

## 이번 검증 결과

TypeScript 검사와 Vite 프로덕션 빌드가 통과했습니다. `npm run verify`로 React 서버 렌더링, 중복 ID 및 내부 앵커, 서비스·추천 탭·FAQ 구성, 필수 항목·연락처·이메일·확인 체크박스 검증과 데모 제출 결과를 확인했습니다. 브라우저 자동화 도구가 제공되지 않아 실제 화면의 반응형 레이아웃과 클릭·키보드 조작은 직접 검증하지 못했습니다. 운영 전 실제 브라우저 및 모바일 기기에서 확인이 필요합니다.

## Vercel 배포 준비

기존 GitHub 저장소를 이용한 배포 설정은 `vercel.json`에 추가했습니다. 사용자 선택에 따라 검토 기간에는 HTML과 HTTP 헤더에 `noindex, nofollow`를 설정합니다. Vercel Hobby의 비상업용 제한을 확인해야 하며, 이번 작업은 로그인·프로젝트 생성·실제 배포를 수행하지 않습니다. 설정값, GitHub `main` 자동 배포 연결, 인증, 환경변수, 정식 도메인 전환 및 배포 후 확인표는 [DEPLOYMENT.md](./DEPLOYMENT.md)를 참고하세요.
